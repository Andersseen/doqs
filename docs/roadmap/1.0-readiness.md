# Doqs 1.0 readiness

Status after 0.12.0: **not declared 1.0-ready.** This document records the contracts as implemented, the evidence for each, and the blockers that remain. It is an inventory, not a feature roadmap: 0.9 added interactive playgrounds, 0.10 content authoring, and 0.11 real-world adoption evidence (Angular Movement and Volt UI built with Doqs pages at their own URLs) plus the contract fixes that evidence demanded (landmarks, a configuration-only entry, incremental migration, API tiers, portability). 0.12 added production-accepted multilingual documentation and reproducible external adoption proofs. Details of the evidence: [consumer parity](../adoption/consumer-parity.md) and [migration findings](../adoption/migration-findings.md).

## Playgrounds (0.9)

- **Contract.** `::playground[id]` + `DoqConfig.playgrounds`. Controls are explicit (`boolean`, `string`, `number`, `select`) and bind by the component's _public_ input name with `createComponent({ bindings })`, so aliases, transforms, required and signal inputs work without private Angular metadata. Outputs are observed with `outputBinding`.
- **Lifecycle.** A control change updates the live component. Reset and a definition change recreate it. Expanding moves the same instance into a native modal `<dialog>`.
- **Not verified / limits.** Overlays appended to `<body>` render below the dialog; controls are not inferred from `doq-api` metadata; object-graph inputs need a wrapper component; screen-reader output was not tested.
- **Adoption findings (Angular Movement `4e71e2f`).** `MoveEnterDirective` is an attribute directive that plays once in `ngOnInit` and exposes no outputs, so the wrapper component re-creates its target element for each input combination and offers its own `played` output. Representable with the public contract; no Doqs change was needed. `pnpm verify:adoption` now proves the live playground against the real checkout.
- **Release finding.** The 0.8.0 release never ran: its eligibility job imported `typescript` before installing dependencies. Fixed and covered by a regression test in 0.9; 0.8.0 reaches npm only if the release workflow publishes it after the merge (npm served 0.7.0 when this was written).

## Content authoring (0.10)

- **Source inclusion contract.** `::source{file, region | lines, lang, title, link}` on a line of its own; text files only, below configured `sourceRoots`, checked on real paths; regions are `doqs:`-prefixed comment markers (nesting allowed, duplicates, misnesting, unterminated and empty regions fail); the result is a fenced block longer than any backtick run in the code.
- **Fragment semantics.** `::include{file}`, fragments live under a `_` path segment, `/x` from the authoring root otherwise relative to the including file, depth 5, cycles and frontmatter rejected, heading levels and links untouched (author responsibility).
- **API link contract.** `[[api:Name|Label@target]]` resolves against the `symbols` index in `.doq-api.json` written by `doq-api`; a target never falls back to another version's index.
- **Versioning.** One target per documentation version, each with its own authoring directory, source roots, API index and optional `revision`; Doqs never fetches an old tag or guesses a source URL.
- **Node-only API stability.** `@doqs/analog/content` and `doq content` are new in 0.10 and Node-only; their shape is covered by `verify:public-api` but stays provisional until a real consumer has used them across a release.
- **Known limitations.** Directives are line-level (literal in quotes, lists, tables); fragment diagnostics point at the fragment; the generated Markdown is committed or generated before the Analog build (the Vite plugin does the latter); new authored pages need a generate (the plugin and `watch` do it).
- **Remaining adoption blockers.** No third-party consumer has authored a real library with it yet; the Angular Movement proof exercises it against a disposable checkout only; Windows paths were not exercised.

## Guarantees

- **Routing.** `<basePath>/<slug>`; `index.md` represents its folder; invalid slugs and duplicate public routes throw naming the files; the first segment `v` is reserved only when versioning is on. Unknown URLs are 404 on static hosting.
- **SSR/SSG.** Every page prerenders and hydrates with no console errors or warnings (E2E fixture enforces this on every test); `docs:check` validates routes, heading ids, TOC fragments, links and canonicals offline on both showcases and the official site.
- **Search.** Optional, static (Pagefind); index holds exactly the documentation pages at canonical URLs (contract tests); search code loads on first query.
- **Versioning.** Optional; archives are independent folders; the current version has one URL per page.
- **API generation.** Deterministic, owns only `--out`, never executes project code.
- **Content authoring.** Deterministic, owns only the files in its manifest, never overwrites a hand-written or edited page, reads only allowed text files, never executes or fetches anything; `check` writes nothing.
- **Theming.** `--host-docs-*` tokens only; no global `html`/`body` rules.
- **Determinism.** `doqDeterministicMarkdown()` contains an upstream race; it does not fix it, and Doqs makes no claim that upstream is fixed.
- **Release.** Version-driven, gated by CI on `main`; npm Trusted Publishing with provenance; no token; the tarball CI verified is the tarball published.

## Compatibility policy

Before 1.0, minors are additive: no removal or incompatible change of anything in the stable list without a deprecation first and a changelog entry. `pnpm verify:public-api` enforces the declaration part against the 0.7.0 baseline (removed exports, retyped members, changed signatures, new required interface members). After 1.0: SemVer: breaking changes only in majors; deprecations live for at least one minor; peer ranges widen only after the compatibility matrix passes for the new version; Node support follows the Node.js release schedule with a minor-version notice before dropping a line.

## Known upstream dependencies and limitations

- Analog's Markdown pipeline renders files concurrently with shared heading state (contained by `doqDeterministicMarkdown()`).
- Analog bundles every Markdown file's frontmatter into the first-loaded JavaScript (about 46–52 B gzip per document); no supported way to defer it.
- Importing any value from `@doqs/analog` in an eagerly loaded chunk keeps the documentation components with it (Angular's compiled classes are not tree-shaken away): the official site measured 260,194 B vs 153,034 B gzip of first-loaded JavaScript for its landing, and avoids the cost by loading the whole region as a lazy route (`apps/site/src/app/docs.routes.ts`).

## 0.11 findings

- **Landmarks (was blocker 1): resolved.** `DoqConfig.landmark`: `'document'` (default) renders exactly one `main` in the index, document and not-found views and a plain container in `DoqShellComponent`; `'host'` renders none. Evidence: `landmarks.spec.ts` (index, document, not found, shell, override, validation), the official-site E2E (`main` count 1, no nested `main`), and both real sites (`main` count 1 in prerendered HTML and hydrated DOM; both shells already wrap the outlet in `<main>`, so both use `'host'`). One visible change for 0.10 users of the shell with the default configuration: the shell no longer adds a second `main`.
- **Configuration import cost (was blocker 2): resolved as a package-boundary fix, with a corrected premise.** `@doqs/analog/config` imports only `@angular/core` and loads in plain Node in about 300 ms; the main entry cannot be imported in plain Node without the Angular compiler. Measured with `pnpm bundle:impact` (same host, lazy documentation route, Vite 8 production build): initial JavaScript is **identical with either entry** (104,812 B gzip landing and documentation page, 229,759 B all JavaScript), because Vite drops unused compiled classes. The earlier claim that a configuration import drags the components into the first chunk does not hold for that scenario; the gain is in tooling contexts, builders that do not tree-shake and the guarantee itself.
- **Incremental migration (new blocker, resolved).** Doqs claimed every URL below its base path, serving host pages as a prerendered 200 "not found". `unmatched: 'continue'` (guard on the content catalog) fixes it; `coexistence.spec.ts` and both real sites cover it. Route order also matters when the host uses a catch-all extra route such as locale wrappers (documented in the guide).
- **Contrast with brand colours (new, resolved).** Text in the primary colour on tinted surfaces failed 4.5:1 with Volt UI's blue; derived `--doq-primary-text` fixes it, axe is clean on both sites in light and dark.
- **Windows line endings (new, resolved).** CRLF checkouts made `doq content check` report generated pages as edited and leaked `\r` into API pages. Fixed in both generators with regression tests; `verify:portable` covers CRLF, junction containment and spaced/non-ASCII paths.
- **Playground overlays (verified limitation).** Inline previews work with real Volt UI dialog, popover and select (focus returns). In the expanded preview (a modal `<dialog>` in the top layer) a select dropdown appended to `<body>` opens beneath it; verified, documented, workaround: use the inline preview. Not fixed: any fix moves consumer nodes between layers or needs an overlay framework.
- **Localization.** Superseded by [0.12 findings](#012-findings): the acceptance that was open at 0.11 is complete.
- **Accessibility.** axe (serious/critical) is clean on both real sites in light and dark and on all existing suites; keyboard journeys cover the drawer, search dialog, playground controls, dialog focus trap and focus restoration in Chromium, Firefox and WebKit. **Screen readers were not tested** (no assistive-technology environment was available). WCAG conformance is not claimed.

## 0.12 findings

- **Localization: production-accepted for the documented contract.** Spec 0015 implemented optional per-locale catalogs and routes, the provider-neutral adapter, Pagefind locale filters, SEO ownership and RTL layout; spec 0019 proved them on production builds of Showcase A (English, Spanish, Arabic; a Spanish archive and no Arabic archive): locale-prefixed prerendered routes, no inferred translations, a real Pagefind index filtered by locale and version, `lang`/`dir`/canonical/`hreflang`, sticky TOC geometry, keyboard and axe checks (Chromium, Firefox, WebKit), and packed consumers on Angular 21 and 22. The host owns the locale lifecycle (an Etyma-style signal stays in the host); there is no Etyma-specific Doqs integration and none is planned for this line.
- **Live SSR status of a missing page (upstream limitation, reproduced in 0.12).** `DoqDocsComponent` sets `RESPONSE_INIT.status = 404` when it claims an unknown URL (for example `/docs/v/1/nope`). Analog 2.9.0's server packages (`@analogjs/router`, `@analogjs/platform`) contain no reference to `RESPONSE_INIT`, so the Analog dev server answers HTTP 200 for it; with `unmatched: 'continue'` Doqs does not claim unknown slugs at all and the host's catch-all answers (also 200 under SSR). Prerendered output served by a static host answers 404. No narrow upstream-supported fix exists, no client-side simulation was added, and the claim is deliberately limited to _static hosting_ for HTTP 404. Class: **U**.
- **External adoption (0.12, [spec 0020](../specs/0020-adoption-release-readiness/spec.md)).** The 0.11 proofs failed against current upstream because they assumed the state of the day they were written, not because Doqs regressed. They are now reproducible: Angular Movement onboarding and in-place route replacement are pinned to `4e71e2f75be3c82ec4f10ca80dc91d08562efa1b` (before it integrated Doqs); `pnpm verify:adoption:existing` rebuilds the integrated `ce9b03d547bc774268768e5f57c028452e70b9ad` with the packed tarball and checks every Markdown route derived from its real content tree; Volt UI is pinned to `7c76ef3b8aa6e3d6c4da578b0be22939556d53af`. Revisions are logged and overridable (`AM_REF`, `AM_EXISTING_REF`, `VU_REF`). Results are in the spec's `verification.md`.
- **Volt UI `MutationObserver is not defined` (upstream, not Doqs).** ng-primitives' `fromMutationObserver` constructs a `MutationObserver` during server rendering. An unmodified Volt UI checkout given only a prerender route list prints the identical error, prerendering completes and all routes are written; the Doqs overlay adds no occurrence and no Doqs frame is on the stack. Earlier "interruption" came from a background run with an open stdin, which the harness now closes. The harness fails on any other uncaught SSR exception.
- **Static layout `route.html`.** Hosts that set `prerender.autoSubfolderIndex: false` emit `docs/x.html`. `doq doctor --build` already handled it; `docs:check` and the preview server did not and now do (repository tooling only).
- **Still open, not caused by 0.12.** Actual VoiceOver/Safari and NVDA sessions, Zone.js on Angular 22, Vite < 8 and Analog > 2.9. A manual protocol is in [browser and screen-reader verification](../operations/browser-and-screen-reader-verification.md); until sessions are recorded, screen-reader evidence remains NOT RUN. Focused Windows Chromium and Linux Firefox/WebKit acceptance pass hosted CI in spec 0021. Optional future work (not blockers): an Etyma-style bridge, a configurable overlay container for the expanded playground.

## Required tests for 1.0

The full `pnpm quality:gate` including `verify:public-api`, `verify:init` and the pinned and integrated adoption proofs (`quality:gate --adoption`); a re-run of the 0.8 contract against the real consumers; resolution of the blockers above with regression tests; and a post-release check that npm serves the new version and the tarball's declarations match `public-api.report.json`.
